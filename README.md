# Poker ok 👌 — Telegram Mini App

Техасский холдем и блекджек **на деньги**: баланс в долларах, пополнение и вывод
криптой через Crypto Bot и xRocket по курсу 1:1. Комната
создаётся по коду, друзья заходят по ссылке из Telegram и играют вечером в своё удовольствие.

## Что умеет

- **Две игры**: безлимитный техасский холдем на 2–9 мест и блекджек на двоих.
- **Открытый список столов**: друзья заходят со своих аккаунтов и сразу видят вашу игру —
  код спрашивать не нужно. Стол можно сделать закрытым, тогда в него пускают только по коду.
- **Отдельный баланс** у каждого игрока: за стол он приносит вход со своего счёта,
  вставая — забирает стек обратно. Баланс переживает перезапуск сервера.
- **Выдача фишек админом** по Telegram ID — командой или из панели в лобби.
- **Пополнение баланса криптой** через Crypto Bot и xRocket: игрок выбирает сумму,
  платит в боте платёжного сервиса, деньги приходят на баланс автоматически.
- **Вывод на кошелёк** тем же путём: с баланса — переводом в Telegram-бот сервиса.
- **Две вкладки**: «Главная» с балансом, активными играми и лентой выигрышей,
  «Игры» со списком открытых столов и созданием своего.
- **Промокоды**: админ выдаёт код на сумму с лимитом активаций, игрок вводит его
  на главной. Один игрок активирует код один раз.
- Единая design system: токены цветов и типографики, один набор SVG-иконок,
  премиальный овальный стол со слоями борта, золотой линией и текстурой сукна.
- Настройка блайндов, стартового стека, числа мест и времени на ход.
- Правильная торговля: блайнды, минимальные рейзы, короткие олл-ины, **сайд-поты**,
  дележ банка при равных руках и возврат непокрытых ставок.
- Таймер хода: кто не успел — автоматический чек или пас, а кто промолчал
  дважды подряд, встаёт из-за стола: его деньги уходят на баланс, стол играет дальше.
- Возврат за свой стек после обрыва связи, автопропуск раздач для отключившихся.
- Пополнение стека, когда деньги за столом закончились.
- Подсказка комбинации над своим местом: «Пара 9», «Стрит до A» — видно только вам.
- История раздач и чат за столом.
- Вид живого стола: деревянный борт, сукно, аватары с бейджами SB/BB/D,
  всплывающие плашки действий, поп-ап победителя, банк по центру.
- Интерфейс рассчитан на телефон.
- Ноль внешних зависимостей: только Node.js (WebSocket-сервер написан вручную).

## Быстрый старт локально

```bash
npm start          # сервер на http://localhost:3000
npm test           # 24 теста: движок, комбинации, подпись Telegram, протокол
```

Без `TELEGRAM_BOT_TOKEN` сервер поднимается в **режиме отладки**: можно открыть
`http://localhost:3000` в обычном браузере, представиться именем и играть.
Чтобы проверить игру вдвоём, откройте вторую вкладку в приватном окне.

## Публикация как Mini App

Telegram открывает мини-аппы только по HTTPS, поэтому нужен домен с сертификатом.

### 1. Бот и приложение в @BotFather

1. `/newbot` — получите токен.
2. `/newapp` — выберите бота, задайте название, описание, картинку 640×360
   и **короткое имя** (например `poker`), а в поле Web App URL укажите адрес вашего сервера.
3. Запомните имя бота и короткое имя приложения — из них собирается ссылка
   `https://t.me/<бот>/<приложение>`.

### 2. Переменные окружения

Приложение читает `.env` из корня проекта (образец — `.env.example`):

```
TELEGRAM_BOT_TOKEN=123456:ABC...      # обязательно: по нему проверяется подпись initData
TELEGRAM_BOT_USERNAME=my_poker_bot    # для кнопки «позвать друзей»
TELEGRAM_APP_SHORT_NAME=poker
TELEGRAM_ADMIN_IDS=123456789          # кто выдаёт деньги
START_BALANCE=10000                   # старт для нового игрока
DATA_DIR=/var/lib/poker               # где хранить балансы
PORT=3000
```

Переменные окружения важнее файла, так что systemd или docker всегда перебьют `.env`.

Проверить токен и повесить кнопку меню бота:

```bash
node scripts/setup-bot.js                           # покажет имя бота и подскажет TELEGRAM_BOT_USERNAME
node scripts/setup-bot.js https://ваш.домен --save  # кнопка «Играть» + имя бота в .env
```

Если что-то не работает, диагностика одной командой:

```bash
sudo bash scripts/doctor.sh
```

**Пошаговая установка на сервер со всеми командами — в [DEPLOY.md](DEPLOY.md).**

### 3. HTTPS

Быстрый путь — один скрипт на сервере (напишет конфиг nginx, проверит DNS и выпустит сертификат):

```bash
sudo bash scripts/setup-https.sh ваш.домен ваша@почта
```

Или руками, например nginx перед приложением:

```nginx
server {
    listen 443 ssl;
    server_name poker.example.com;

    # сертификат от certbot

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;      # обязательно для WebSocket
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;
    }
}
```

Или в контейнере:

```bash
docker build -t poker-friends .
docker run -d -p 3000:3000 -e TELEGRAM_BOT_TOKEN=... poker-friends
```

Для разовых посиделок хватит и туннеля (`cloudflared tunnel --url http://localhost:3000`):
полученный HTTPS-адрес вставьте в настройки приложения у @BotFather.

## Пополнение и вывод

Раздел «Пополнить баланс» появляется в лобби сам, как только в `.env` задан токен
хотя бы одного из сервисов. Ничего не задано — приложение работает как раньше,
деньги выдаёт только админ.

### 1. Получить токен

- **Crypto Bot** — в [@CryptoBot](https://t.me/CryptoBot): Crypto Pay → My Apps →
  Create App → API Token. Для проверки без настоящих денег есть тестовая сеть:
  токен берётся в [@CryptoTestnetBot](https://t.me/CryptoTestnetBot),
  в `.env` добавляется `CRYPTOBOT_TESTNET=1`.
- **xRocket** — в [@xRocket](https://t.me/xrocket): Rocket Pay → Create App → API token.

### 2. Прописать в `.env`

```sh
CRYPTOBOT_TOKEN=12345:AAxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
XROCKET_TOKEN=xxxxxxxxxxxxxxxxxxxxxxxx

TOPUP_CURRENCY=USDT      # монета, в которой выставляются счета
TOPUP_USD_PER_UNIT=1     # 1 USDT = $1.00 — курс 1:1 в обе стороны
TOPUP_PRESETS=1,5,10,25  # кнопки быстрых сумм
TOPUP_MIN_AMOUNT=0.1
TOPUP_MAX_AMOUNT=1000
WITHDRAW_MIN_AMOUNT=1    # минимальная сумма вывода, $
```

Достаточно одного токена — второй сервис просто не появится в списке.

`TOPUP_USD_PER_UNIT` меняйте только вместе с `TOPUP_CURRENCY`: 1:1 верно для
долларового стейблкоина, а для TONCOIN курс будет другим и плавающим.

### 3. Указать адрес вебхука

В настройках приложения внутри самого бота (Crypto Bot: My Apps → Webhooks;
xRocket: настройки приложения) пропишите:

```
https://ваш-домен/pay/cryptobot/webhook
https://ваш-домен/pay/xrocket/webhook
```

Адреса должны быть на HTTPS — их поднимает `scripts/setup-https.sh`.

Вебхук не обязателен: пока мини-апп открыт, он сам опрашивает статус счёта
раз в три секунды, и деньги придут и так. Но если игрок закроет приложение,
не дождавшись подтверждения, зачислит их именно вебхук.

### Как устроен вывод

Вывод — это перевод с баланса приложения на Telegram-аккаунт игрока внутри
платёжного сервиса (`transfer` у Crypto Bot, `/app/transfer` у xRocket).
Чтобы он работал, на балансе приложения должны быть деньги — те самые,
что пришли от пополнений.

Порядок намеренно такой:

1. Сумма **списывается с баланса до** обращения в сервис. Два одновременных
   запроса не смогут вывести одни и те же деньги дважды.
2. Уходит перевод с ключом идемпотентности (`spend_id` / `transferId`) —
   повтор с тем же ключом не создаст второй перевод.
3. Сервис **внятно отказал** (нет средств, игрок не запускал бота) — деньги
   возвращаются на баланс сразу.
4. Сервис **не ответил** (обрыв связи, таймаут, 5xx) — деньги **не**
   возвращаются: перевод мог пройти, и возврат означал бы выплату дважды.
   Выплата помечается как «в обработке», игрок видит честный статус.

Разобрать зависшие выплаты можно командой в чате стола:

| Команда | Что делает |
| --- | --- |
| `/выплаты` | показать выплаты, по которым нет ясного ответа |
| `/повторить <id>` | повторить перевод (безопасно: ключ идемпотентности тот же) |

Вывод доступен только при входе через Telegram: перевод уходит по числовому
Telegram ID, которого у отладочного входа нет.

### Как это устроено

1. Игрок выбирает сумму — сервер заводит у себя запись о счёте и просит
   платёжный сервис выставить счёт, передавая ему идентификатор этой записи.
2. Открывается бот платёжного сервиса, игрок платит.
3. Сервис присылает вебхук. Подпись проверяется по HMAC-SHA256 с ключом
   `sha256(токен)` **по сырому телу запроса** — подделать её, не зная токена,
   нельзя. Не совпала — ответ 403 и никаких начислений.
4. Деньги зачисляются **ровно один раз**: у записи есть отметка о зачислении,
   поэтому повторный вебхук и параллельный опрос из мини-аппа её не задвоят.
5. Зачисляется столько, сколько реально оплачено, — переплата не теряется.

Все суммы и лимиты проверяются на сервере: клиент не может ни назначить себе
курс, ни закрыть чужой счёт, ни начислить себе денег без подтверждения сервиса.
Счета на пополнение хранятся в `payments.json` рядом с балансами.

> Это игра на реальные деньги: с пополнением и выводом она подпадает под
> регулирование азартных игр в большинстве юрисдикций и почти наверняка
> требует лицензии. Проверьте это отдельно, до запуска на публику.

## Как играют

1. Один человек открывает приложение и жмёт **Создать стол**.
2. Остальные открывают то же приложение — созданный стол уже виден в списке
   **«Открытые столы»**, достаточно нажать «Играть». Код и ссылки не нужны.
3. Все садятся на свободные места, хозяин стола нажимает **Начать игру**.
4. Раздачи идут одна за другой, пока хозяин не поставит паузу.

Если стол нужен только для своих, снимите галочку «Открытый стол» при создании:
тогда он исчезнет из общего списка, а зайти в него можно будет по коду из пяти символов
или по ссылке из кнопки **＋** (`https://t.me/<бот>/<приложение>?startapp=КОД`).

### Баланс и деньги за столом

У каждого игрока есть **баланс** — общий счёт в приложении, не привязанный к столу:

- при первом входе начисляется `START_BALANCE` фишек (по умолчанию 10 000);
- когда игрок садится за стол, вход списывается с баланса и превращается в стек;
- когда встаёт — стек возвращается на баланс (если это случилось посреди раздачи,
  место освободится и деньги вернутся после вскрытия);
- кнопка «Пополнить стек» дотягивает стек до размера входа, тоже с баланса;
- балансы лежат в `DATA_DIR/accounts.json` и переживают перезапуск.

Кроме пополнения криптой, деньги на баланс может начислить **админ**. Админы задаются переменной
`TELEGRAM_ADMIN_IDS` (Telegram ID через запятую). У админа в лобби появляется карточка
«Админ: балансы»: поле для ID, сумма в долларах и кнопки «Выдать», «Забрать», «Выставить»,
плюс список счетов — тап по строке подставляет игрока в поле.

То же самое командами в чате стола:

| Команда | Что делает |
| --- | --- |
| `/дать 123456789 50` | начислить $50.00 на баланс |
| `/забрать 123456789 1000` | списать с баланса |
| `/установить 123456789 10000` | выставить точный баланс |
| `/баланс 123456789` | посмотреть чужой баланс |
| `/счета` | список счетов |
| `/промокод ЛЕТО 5 100` | код ЛЕТО на $5.00, 100 активаций |
| `/промокоды` | список кодов |
| `/удалить-код ЛЕТО` | убрать код |
| `/баланс` | свой баланс (доступно всем) |
| `/id` | свой Telegram ID (доступно всем) |
| `/помощь` | список команд |

**Адресат — Telegram ID или `@ник`, но не имя**: имена в Telegram повторяются,
и по ним легко начислить не тому. Свой ID игрок видит в лобби и может скопировать одним тапом.
Админ может ещё тапнуть по игроку за столом — откроется та же выдача, уже с подставленным ID.

### Блекджек на двоих

Отдельный тип стола: выбирается при создании комнаты. **Дилера нет** — играют двое
между собой, кто ближе к 21, тот и забрал банк:

- оба ставят поровну; сумму назначает тот, чья очередь ходить первым;
- очередь начинать переходит по кругу каждую раздачу;
- по две карты каждому, **карты соперника закрыты до конца раздачи** — иначе,
  видя чужую руку, легко решить за него, брать ещё или хватит; в журнале
  тоже не пишется, какую карту взял соперник, только сам факт;
- ход по очереди: взять ещё карту или остановиться;
- **перебор не заканчивает раздачу**: соперник ходит вслепую и может перебрать
  следом — тогда ничья, никто ничего не теряет;
- равные суммы — ничья, деньги остаются при своих;
- 21 с двух карт добирать не даёт и выигрывает у меньшей суммы, но платит ровно
  ставку: полторы платит казино, а казино тут нет;
- не успел походить — останавливаешься; не успел назначить ставку — ставится минимум.

Деньги только переходят между двумя игроками, ниоткуда не берутся — как и в холдеме.

### Подсказка комбинации

Над своим местом видно, что уже собралось: «Пара 9», «Стрит до A», «Фулл-хаус 7 на 2».
Комбинация считается на сервере только по тем картам, которые игрок и так видит,
поэтому подсмотреть чужую руку через неё нельзя — чужие комбинации появляются
только на вскрытии.

## Устройство проекта

```
server/
  index.js          HTTP, статика, маршрутизация команд по WebSocket
  accounts.js       балансы игроков и права админа, хранение на диске
  env.js            чтение .env
  wsserver.js       свой минимальный WebSocket (RFC 6455)
  telegram.js       проверка подписи initData
  room.js           стол: места, стеки, таймеры, состояние для клиента
  money.js          деньги: целые центы внутри, «$12.34» наружу
  promo.js          промокоды: выдача админом, разовая активация
  payments/
    index.js        счета на пополнение и выплаты, разовое зачисление, хранение
    common.js       HTTP-запрос и проверка подписи вебхука
    cryptobot.js    Crypto Pay API (@CryptoBot)
    xrocket.js      xRocket Pay API (@xRocket)
  poker/
    cards.js        колода и тасование
    evaluator.js    оценка комбинаций, лучшие 5 из 7
    hand.js         одна раздача: торговля, банки, вскрытие
public/             мини-апп: index.html, styles.css, app.js
test/               тесты движка, комбинаций, подписи и протокола
```

Игровая логика живёт **только на сервере**: клиент присылает намерения и рисует
присланное состояние. Чужие карты до вскрытия просто не покидают сервер, поэтому
подсмотреть их в браузере нельзя.

## Ограничения

- Столы хранятся в памяти: перезапуск сервера их закрывает (деньги со столов при этом
  возвращаются на балансы, а балансы сохраняются на диск).
- Пустая комната живёт полчаса, потом удаляется.
- Одно активное подключение на игрока — вторая вкладка вытесняет первую.
- Лента «Последние выигрыши» живёт в памяти: перезапуск сервера её очищает.
- Вывод возможен, пока на балансе приложения в платёжном сервисе есть деньги.
- Открытый стол видит любой, кто запустил приложение вашего бота, а не только друзья.
  Если бот публичный, а компания закрытая — создавайте стол с выключенной галочкой
  «Открытый стол» и зовите по коду.
