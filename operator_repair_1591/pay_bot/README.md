# Бот оплаты eSIM (полуавтомат) — ОТДЕЛЬНЫЙ бот

Отдельный Telegram-бот: кидаешь ему ссылки заказа и карту — он сам открывает,
жмёт «Оплатить», вводит карту и доходит до страницы банка, а код из SMS вводишь ты.
Основного beeline-бота не трогает.

**Важно:** у этого бота должен быть **свой** токен (отдельный бот от @BotFather).
Нельзя использовать токен основного бота — будет конфликт (ошибка 409).

Сейчас готово: ссылка → «Оплатить» → форма карты → оплата → 3DS (код, повтор при неверном,
отчёт при отказе). Страница успеха и автополучение QR — добавим после первого реального
примера (пока бот после успешного кода присылает скрин страницы и ссылку).

Распознавание поля 3DS-кода усилено (PAY_3DS_1591R103): ищет поле по признакам самого инпута
(`autocomplete="one-time-code"`, `inputmode=numeric`, `type=tel/number`, короткий `maxlength`,
единственное поле на странице) во всех фреймах, а не только по подписи рядом — ловит больше форм.

Итог оплаты читается из финальной ссылки (PAY_STATUS_1591R103): `...&status=success` — прошла,
`...&status=fail` — не прошла. После принятого кода бот ~20-40 сек ждёт «ответ от банка» и
читает статус из URL, а не выдаёт успех раньше времени.

Ошибка «оплата не прошла»:
- ДО кода / без 3DS (сразу после ссылки или «Оплатить картой», либо `status=fail` в URL до банка) —
  это сбой на стороне Билайна: бот сам жмёт «попробовать ещё раз» и вводит карту заново, до
  `beeline_retry_max` раз (по умолч. 3), с пушем «Оплата не прошла моментально, ошибка Билайна».
- ПОСЛЕ ввода 3DS-кода (`status=fail`) — это проблема карты: бот пишет «возможно, недостаточно
  средств либо карта заблокирована; если картой уже оплачивали Билайн более 3 раз — сервис может
  блокировать» и даёт две кнопки: **🔁 Повторить этой картой** и **💳 Ввести новую карту**
  (можно просто прислать новую карту текстом «НОМЕР СРОК КОД», или «отмена» — пропустить ссылку).

## Установка одной командой (рекомендуется)

На сервере (Ubuntu). Сам скачает бота, спросит токен, chat_id и прокси Telegram, настроит и запустит службу:

```
curl -fsSL https://raw.githubusercontent.com/nik236098-dotcom/tess/codex/operator-observer-15.87/operator_repair_1591/pay_bot/install_pay_bot | sudo bash
```

Спросит по очереди:
- **Токен этого (платёжного) бота** — отдельный бот от @BotFather, НЕ токен beeline (иначе ошибка 409).
- **chat_id** — куда бот пишет.
- **Прокси для Telegram** — та же строка, что у beeline, например `socks5h://логин:пароль@хост:порт`
  (или `direct`, если Telegram открывается с сервера напрямую). Без прокси из России Telegram не ответит.
- **Прокси для страниц оплаты** — обычно не нужен, жми Enter (оплата идёт напрямую).

Если на сервере уже стоит beeline — установщик переиспользует его venv с playwright и Chromium
(ставить браузер заново не надо). Иначе поставит свой venv и Chromium сам.

Проверка:
```
systemctl is-active pay_bot
sudo journalctl -u pay_bot -f -o cat
```

Потом напиши боту `/start`.

## Установка вручную (альтернатива)

1. Скачать бота (ветка та же):

```
sudo mkdir -p /opt/pay_bot && sudo curl -fsSL https://raw.githubusercontent.com/nik236098-dotcom/tess/codex/operator-observer-15.87/operator_repair_1591/pay_bot/pay_bot.py -o /opt/pay_bot/pay_bot.py
```

2. Создать конфиг (подставь свой токен ВТОРОГО бота, chat_id и прокси для Telegram):

```
sudo tee /opt/pay_bot/pay_bot_config.json >/dev/null <<'JSON'
{
  "token": "ТОКЕН_ВТОРОГО_БОТА",
  "chat_id": "ТВОЙ_CHAT_ID",
  "proxy": "socks5h://логин:пароль@хост:порт",
  "headless": true,
  "code_wait_seconds": 300,
  "page_wait_seconds": 240
}
JSON
sudo chmod 600 /opt/pay_bot/pay_bot_config.json
```

(`proxy` — тот же, что у Telegram в основном боте; если Telegram открывается напрямую — поставь `"direct"`.
Если страницы оплаты надо открывать через прокси — добавь строку `"browser_proxy": "socks5://..."`.)

3. Запустить как службу (использует venv основного бота — там уже есть playwright и requests):

```
sudo tee /etc/systemd/system/pay_bot.service >/dev/null <<'UNIT'
[Unit]
Description=Beeline eSIM pay bot (semi-auto)
After=network-online.target

[Service]
Type=simple
Environment=PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers
ExecStart=/opt/beeline/venv/bin/python /opt/pay_bot/pay_bot.py
WorkingDirectory=/opt/pay_bot
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
UNIT
sudo systemctl daemon-reload && sudo systemctl enable --now pay_bot
```

Если Chromium лежит в другом месте (не `/opt/pw-browsers`), убери строку `Environment=PLAYWRIGHT_BROWSERS_PATH=...`
— playwright найдёт свой стандартный путь. Проверить службу:

```
sudo systemctl status pay_bot --no-pager
sudo journalctl -u pay_bot -f -o cat
```

## Как пользоваться

1. Напиши второму боту `/start`.
2. Пришли одну или несколько **ссылок** заказа (которые ждут оплаты) — каждую строкой или в одном сообщении.
3. Пришли **карту** одним сообщением:  `НОМЕР СРОК КОД`
   например: `2200000000001036 06/34 123` (номер можно и группами: `2200 0000 0000 1036 06/34 123`).
4. Бот начнёт оплачивать ссылки по очереди. Когда дойдёт до банка — попросит код; пришли код из SMS/пуша.
   - под запросом кода есть кнопка **📨 Повторить СМС** — запросить код заново (бот нажмёт «отправить код
     повторно» на странице банка; если идёт отсчёт — напишет, сколько ждать; если кнопки нет — сообщит);
   - «код неверный» → пришли код заново (до 5 попыток);
   - итог оплаты бот берёт из финальной ссылки: `status=success` — прошла, `status=fail` — не прошла;
   - **оплата не прошла** (сразу без 3DS) → бот сам повторяет той же картой до 3 раз;
   - **оплата не прошла после кода / 5 неверных кодов** → кнопки **🔁 Повторить этой картой** и
     **💳 Ввести новую карту** (или новая карта текстом, или «отмена» — пропустить ссылку); ссылка не теряется;
   - успех → бот присылает скрин страницы после оплаты (автополучение QR добавим позже).
5. `/stop` — сбросить очередь и карту. Карта и так стирается из памяти после прогона.

Карта хранится только в памяти процесса, в файлы не пишется.
