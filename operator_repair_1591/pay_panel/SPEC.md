# Панель оплат eSIM — ТЗ (pay_panel)

Многопользовательский Telegram-бот: админ (владелец) раздаёт ссылки на оплату, операторы
(«оплатчики») по очереди оплачивают их своими картами и получают ставку в крипте за каждый успех.
Движок оплаты (ввод карты, 3DS, YooMoney, определение status=success/fail) переиспользуется из
`pay_bot` (`operator_repair_1591/pay_bot/pay_bot.py`).

Отдельный бот со своим токеном. Все данные — в SQLite (переживает перезапуск, бэкапится).

---

## 1. Роли
- **Гость** — не авторизован. Видит только запрос кода доступа + контакт админа.
- **Оплатчик** — авторизован по инвайту. Видит панель оплатчика.
- **Админ** — владелец (фиксированный Telegram ID в конфиге). Видит панель админа. Инвайт не нужен.
- **Забанен** — на любой запрос: «⛔ Вы заблокированы. Причина: … Поддержка: @gennadiy_cc».

## 2. Доступ и инвайты
- Вход **только по приглашению**. Гость шлёт код доступа; неверный/использованный → отказ.
- Админ: `/invite <код>` — создаёт **одноразовый** код. Первый, кто введёт его, становится оплатчиком
  (атомарно — гонка двух вводов отдаётся первому).
- Гостю показывается контакт админа (@gennadiy_cc) для запроса кода.

## 3. Очередь (строго по одному)
- Параллельной работы нет: пока один оплатчик работает, остальные ждут (иначе Билайн банит IP/eSIM).
- «Встать в очередь» → ждёт; придёт пуш «твоя очередь». «Выйти из очереди» — доступно всегда.
- Авто-освобождение: **3 мин** без действий; **5 мин** после «Ввести новую карту». Причина выхода:
  «ответа не поступило». Текущая ссылка при этом возвращается в очередь (исход ABORTED).
- Пауза между оплатами не ставится: status=success → ссылка закрывается, берётся следующая.

## 4. Исход каждой попытки оплаты (основа логики)
- ✅ **SUCCESS** — успех: баланс += ставка; счётчик успехов карты += 1.
- ❌ **DECLINE** — реальный отказ карты/банка: идёт в счётчик предупреждений оператору.
- 🌐 **SITE_PROBLEM** — временная проблема сайта/сети: ссылка в очередь, оператор НЕ наказан.
- 🗄 **BAD_LINK** — ссылка непригодна (нет кнопок оплаты, «заказ не найден», «уже оплачен», истёк):
  в архив проблемных ссылок админу, оператор НЕ наказан, оператору ссылка пропускается тихо.
- ⚪️ **ABORTED** — оператор ушёл/таймаут/не распознан банк: ссылка в очередь, оператор НЕ наказан.

Только **DECLINE** влияет на предупреждения. Всё остальное оператору не в минус.

## 5. Проверка карты на старте (отсекаем мусор до работы)
Карта `НОМЕР СРОК КОД` принимается только если всё верно, иначе
«⚠️ Карта не принята: <причина>. Пришли заново: НОМЕР СРОК КОД» и работа не начинается:
- первая цифра **2** (Мир), **4** (Visa) или **5** (Mastercard);
- ровно **16 цифр** в номере;
- срок **MM/YY**, месяц **01–12**;
- **CVV ровно 3 цифры**.
(Просрочку и алгоритм Луна НЕ проверяем — просроченная карта может быть активна.)

## 6. Лимит карты
- Жёсткий лимит Билайна: **3 успешные оплаты** с одной карты (по номеру карты, глобально по всем
  операторам и времени). Счётчик = число успешных оплат этой карты; отмена успеха уменьшает счётчик.
- Если оператор вводит карту, уже имеющую 3/3 — сразу «эта карта исчерпана», в работу не берём.
- После 3-й успешной: «Карта использована 3/3, больше нельзя» → «Ввести новую карту» / «Закончить».

## 7. Предупреждения оператору
- После **3 реальных DECLINE подряд** (не ошибок Билайна, не BAD_LINK, не ABORTED) к сообщению о провале
  добавляется: «⚠️ При множестве неудачных оплат ваш аккаунт может быть ограничен.»
- Предупреждение повторяется на каждом провале, пока оператор не сделает хотя бы 1 успех (счётчик сброс).
- Это **только предупреждение**. Блокировку принимает только админ (вручную).
- На реальном провале также текст: «Если этой картой уже платили раньше (сам или кому-то) — Билайн может
  отклонять сам; 3 оплаты — его жёсткий лимит.»

## 8. Экономика
- Оператор платит **своей** картой (~300 ₽ за тариф) и получает **ставку** (по умолч. 4.5 $) за успех;
  ставка уже включает возмещение. Баланс — в **долларах**.
- Выплаты — вручную админом (крипта), автооплаты нет.
- «Запросить выплату» = весь баланс. Баланс переходит в **заморозку** (не жёсткий ноль):
  админ «Выплачено» → списано; «Заблокировать» → возвращается оператору.
- **Отмена оплаты** (чарджбек/договор не подписан): минус ставки с баланса (можно в минус),
  −1 к счётчику успехов карты. Оператору коротко: «❗️ Одна из оплат отменена, снято с баланса X $.
  Оспорить: @gennadiy_cc». Подробности не расписываем.

## 9. Нераспознанный 3DS → интерактивный ИИ-агент
Когда реально дошли до 3DS, а поле кода/кнопку авто-детект (признаки инпута, все фреймы, единственное
поле) не нашёл:
1. Бот шлёт **скрин** + «⚠️ Не могу сам найти поле кода». Кнопки: **[🤖 Вызвать ИИ-агента] [🚫 Отменить оплату]**.
2. «Вызвать ИИ» → «Подскажи простыми словами, где поле ввода кода и что нажать».
3. Оператор пишет словами → пуш «🤖 ИИ-агент работает…».
4. Пуш «Поступил ответ от ИИ-агента: <короткая фраза>» + **[💬 Ответить ИИ] [🚫 Отменить оплату]**.
5. Максимум **2 попытки** объяснить. Не вышло → ИИ коротко сообщает, оплата отменяется (исход ABORTED,
   ссылка в очередь), оператору: **[💳 Другая карта] [🚪 Закончить]** + текст «можно отдать на ручную
   оплату — напиши @gennadiy_cc».
6. Успех/провал определяет **софт по странице** (status, исчезновение поля), не ИИ.

**Безопасность ИИ — by design, а не только промтом.** ИИ не выполняет произвольные команды. Ему даётся
список элементов страницы (видимые поля и кнопки с их текстом/плейсхолдерами, пронумерованные) + слова
оператора + код из СМС (его прислал оператор). ИИ возвращает СТРОГО структуру:
`{"fill": {"index": N, "value": "<код>"}, "click": {"index": M}}` либо `{"status": "not_found"}` либо
`{"status": "off_topic"}`. Бот выполняет только fill/click по индексам реальных элементов. «Закрой
браузер / выключи сервер / покажи код» невыполнимы — таких действий в наборе нет.

**Правила ответов ИИ (промт):**
- Любой вопрос не по теме → `off_topic`, бот отвечает: «Давай по теме — куда нажимать на этой странице».
- Коротко, чётко, простой русской речью (англ. слова допустимы, если так на странице: send code again,
  repeat). Без «поэм».
- Никакого кода сайта, никаких объяснений на языке программиста («POST вернул decline» — запрещено).
  По-человечески: «нажал кнопку, сайт ничего не показал — возможно, есть другой вариант?».
- Провайдер: DeepSeek (уже подключён), запрос по **тексту** DOM (не по скриншоту) — быстро.

## 10. Движок оплаты (из pay_bot) и его исходы
Переиспользуется логика: открыть ссылку → «Оплатить» → ввод карты → ожидание банка → 3DS (с кнопкой
«📨 Повторить СМС») / YooMoney-PUSH (с «📲 Получить код по СМС») → чтение итога из URL
(`status=success`/`status=fail`). Мгновенная «оплата не прошла» до 3DS → авто-повтор той же картой
до 3 раз (ошибка Билайна). После 3DS fail / 5 неверных кодов → ветка «та же / новая карта».

## 11. Проблемные ссылки
Нет кнопки «перейти к оплате» / заказ не найден / истёк → оператору тихо пропускается, админу пуш:
«🗄 Проблемная ссылка <url>, причина …» + **[♻️ Вернуть в очередь] [🗑 Удалить]**. До действия админа
лежит в архиве и в очередь оплат не попадает.

## 12. Отказоустойчивость («работа не виснет никогда»)
- **Watchdog на 1 оплату** (напр. 8–10 мин): превысили — abort, ссылка в очередь, скрин админу.
- На каждый сетевой шаг — таймаут + 2–3 ретрая; при недоступности сайта → SITE_PROBLEM (не наказываем).
- Серия «странных» отказов, похожих на бан IP → авто-пауза приёма оплат + пуш админу.
- Серия ненаходок кнопки «оплатить»/формы → пуш админу «возможно, сайт изменился» + скрин.
- **Перезапуск бота** посреди оплаты: живой браузер потерян → активную ссылку в очередь, оператору пуш,
  очередь освобождается. Балансы/очередь в SQLite целы.
- Chromium упал → перезапуск; диск забит скринами → чистка; Telegram лагает → ретраи;
  канал логов недоступен → фолбэк в ЛС админу.

## 13. Канал логов
- Финал каждой оплаты: скрин + ссылка + какой оператор + карта (маск.) + время (МСК).
  Кнопка **[🚫 Отмена оплаты]** (только для успешных).
- Запросы на выплату со статусом (в ожидании / заблокировано / успешно) + ✅/🚫 (пометки только для админа).
- Выбор канала: бот предлагает каналы, где он **админ**.

## 14. Команды админа
- `/invite <код>` — одноразовый код доступа.
- `/ban @тег|ID причина` — бан навсегда.
- `/unban @тег|ID` — разбан (оператору пуш о разбане).

## 15. Меню (оформление)
См. согласованные макеты (панель оплатчика, панель админа, канал логов) — компактные блоки с эмодзи,
разделители `━━━`, inline-кнопки. Валюты показываются раздельно: баланс/ставка в `$`, тариф в `₽`.

## 16. Данные (SQLite, черновик схемы)
- `operators(id, tg_id, username, balance_usd, frozen_usd, rate_usd, rate_until, success_today,
  decline_today, success_total, fail_streak, created_at, banned, ban_reason)`
- `invites(code, created_by, used_by, used_at)`
- `links(id, url, status[queued|in_progress|paid|problem|deleted], added_at, paid_by, reason)`
- `cards(card_hash, success_count)` — глобальный счётчик успехов по карте.
- `payments(id, link_id, operator_id, card_mask, result, amount_usd, url_final, at, canceled)`
- `payouts(id, operator_id, amount_usd, status[pending|paid|blocked], requested_at, decided_at)`
- `queue(position, operator_id, joined_at, last_action_at)`
- `settings(default_rate_usd, tariff_rub, log_channel_id, accepting_bool, admin_id)`
Регулярный бэкап файла БД + команда выгрузки.

## 17. Конфиг (pay_panel_config.json, секреты не в репозитории)
`token, admin_id, admin_contact(@gennadiy_cc), proxy(telegram), browser_proxy, deepseek_api_key,
deepseek_model, default_rate_usd=4.5, tariff_rub=300, idle_timeout_s=180, newcard_timeout_s=300,
per_payment_watchdog_s=600`.

## 18. План сборки (этапы)
1. Каркас: роли, инвайты, SQLite, панель оплатчика/админа (меню без оплаты), баны/`/unban`.
2. Очередь + движок оплаты + проверка карты + лимит карты + балансы + исходы.
3. Проблемные ссылки, предупреждения, отмена оплаты, выплаты (заморозка), статистика.
4. Канал логов, выбор канала, временные ставки с авто-возвратом.
5. ИИ-агент (нераспознанный 3DS), авто-пауза при бане IP, watchdog, бэкапы.
