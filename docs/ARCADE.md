# Plinko, Башня, Keno, Дракон и Тигр

Четыре одиночные игры в общей фиолетовой теме. Колесо не добавлено.

## Правила и источники

## Отличия и расчёты

- Plinko ограничен 10 рядами и тремя классическими рисками; остальные настройки Stake не реализованы. Keno содержит только Classic.
- Для Башни коэффициент этажа n: `round(0.98 * (columns / safe)^n, 2)`. Это расчёт по опубликованным вероятностям и RTP, а не сверка каждой ячейки таблицы казино.
- В Драконе и Тигре восемь колод перемешиваются заново перед каждым одиночным раундом. Дополнительных ставок на масть и прочее нет.
- Коэффициенты означают общую выплату со ставкой. Деньги хранятся в центах; итог округляется вниз до цента. Поэтому фактическая отдача на малых ставках может быть ниже табличной.
- В Башне ставка $1–$1000 на всех пяти сложностях. В остальных новых играх минимум $0.10, максимум $1000. Внутренний лимит баланса увеличен до $10 млрд: это позволяет полностью зачислить выигрыш последнего этажа Master при ставке $1000 ($256 901 120), без уменьшения коэффициента или выплаты. Суммы по-прежнему целочисленные центы, ниже предела точности JavaScript.
- Plinko поддерживает 1, 5, 10 или 25 шариков за запуск. Ставка в поле относится к одному шарику. Общая стоимость показывается до запуска, снимается единой операцией; каждый путь выбирается независимо. Каждая выплата округляется до цента отдельно, затем все выплаты суммируются. Недостаток средств на весь запуск отклоняет его полностью. Один запрос/одна ревизия защищает весь запуск от повторного списания. Новый запуск доступен после завершения текущей анимации; итоговая плашка показывается один раз по сумме всех шариков. При переподключении возвращается сохранённый общий результат.

- Используется серверный криптографический `randomInt`. Проверка игроком через server seed / client seed, как в Provably Fair Stake, не реализована.

## Сохранение и проверки

Ставка, результат и баланс сохраняются до подтверждения клиенту. Ошибка записи отменяет изменения в памяти. Повторный запрос с прежней ревизией не списывает деньги повторно. Незавершённая Башня восстанавливается после перезапуска; будущие ловушки не отправляются клиенту. Если выплата не помещается в лимит баланса, она сохраняется целиком как ожидающая и не теряется.

Автоматические проверки запускаются командой `node --test test/*.test.js`. Среди проверок: все 1024 пути Plinko для каждого риска, все количества совпадений Keno, пять сложностей Башни, ничья Dragon/Tiger, повторные запросы, восстановление с диска, ошибка записи, анимации и отмена анимации при выходе, обмен через WebSocket.

Исправлено закрытие списка сложности Башни: нажатие на нативный select больше не заменяет его DOM-элемент. Диапазон $1–$1000 синхронизирован между сервером, полем суммы, кнопкой MAX и проверкой ручного ввода; выбор сложности блокируется на время текущего раунда.

В Plinko единая геометрия используется для отрисовки и движения (`public/plinko-motion.js`). Падение длится около 4.4 секунды: ускорение вниз, контакт с верхней поверхностью штырька, отскок вверх, следующая дуга. После последнего ряда шар падает внутрь открытой лунки и остаётся на её дне. Коэффициент расположен отдельно под лункой. Для всех 1024 путей проверяются зазоры со всеми штырьками с шагом 8 мс; отдельно проверяются непрерывность контактов и разворот вертикального движения. Результат и выплаты по-прежнему определяет сервер.

Тесты интерфейса выполняются с моделью DOM: они не подтверждают внешний вид на iPhone. Визуальная проверка работающего локального приложения в браузере недоступна в этой среде; необходимо проверить в Telegram после установки.

## Установка на сервере

```bash
cd /opt/poker/app && sudo -u poker git fetch origin codex/crash && sudo -u poker git show FETCH_HEAD:scripts/crash-update.sh | sudo bash
```

Полностью закрыть и снова открыть мини-приложение после установки.

Лунки Plinko уменьшены с 31 до 20 единиц высоты и подняты ближе к нижнему ряду (зазор 15 вместо 30). Поле имеет пропорции 360×310; коэффициенты компактно расположены под лунками. Шарики запускаются с интервалом 100 мс и летят одновременно; счётчик выплат растёт после приземления каждого. Проверки покрывают суммы запусков, защиту от повторов, недостаток средств и полную выплату Master.
