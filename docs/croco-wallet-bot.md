# Croco: кошелёк, рефералы и Telegram-бот

Эта версия реализует согласованные экраны кошелька, профиля, бонусов и информации.
Аватар и имя берутся из Telegram. В истории игр отображаются все завершённые ставки:
миниатюра игры, ник, ставка, фактический коэффициент выплаты и чистый результат.
Нажатие раскрывает время, выплату и ID. Серия шариков Plinko записывается по одному
шарику. Старые проигрыши восстановить невозможно: их предыдущая версия не хранила.
Существующие платёжные записи импортируются при первом запуске.

## Обновление

```bash
cd /opt/poker/app && sudo -u poker git fetch origin codex/crash && sudo -u poker git show FETCH_HEAD:scripts/crash-update.sh | sudo bash
```

Скрипт проверяет JavaScript, изображения и все 52 классические карты до остановки
сервиса. После запуска ждёт два успешных HTTP-ответа. Доступ к серверу и Telegram
каналам не нужен для локальных тестов; реальный запуск выполняется на вашем сервере.

## Настройка бота

Используется существующий `TELEGRAM_BOT_TOKEN`. Администраторы берутся только из
`TELEGRAM_ADMIN_IDS` (числовые Telegram ID через запятую). Три слота Abyss, Cryo Vault
и Midnight Express видны и доступны только администраторам. Остальные игры не скрыты.

Адрес приложения берётся из `PUBLIC_APP_URL`, затем `TOPUP_RETURN_URL`, затем
из существующей кнопки меню Telegram. `SUPPORT_URL` задаёт контакт поддержки.
`TERMS_URL` и `PRIVACY_URL` ведут на ваши опубликованные документы: юридические
условия в этой версии не выдумываются. Пока URL не задан, раздел сообщает,
что документ не опубликован, и предлагает связаться с поддержкой.

Бот запускается внутри `poker.service` и получает события через long polling.
Если у бота уже установлен webhook, он не удаляется автоматически. Для перехода:

```bash
cd /opt/poker/app && sudo -u poker node scripts/setup-bot.js --polling && sudo systemctl restart poker
```

`TELEGRAM_BOT_RUNTIME=0` выключает обработчик бота, не отключая Mini App.
Не запускайте второй polling-процесс с тем же токеном.

Добавьте бота администратором трёх приватных каналов с правом публикации.
Затем **в личном чате с ботом со своего admin-аккаунта**:

```text
/setchannel payouts -100_ID_КАНАЛА_ВЫВОДОВ
/setchannel events -100_ID_КАНАЛА_ПОПОЛНЕНИЙ_И_РЕГИСТРАЦИЙ
/setchannel games -100_ID_КАНАЛА_ИГРОВЫХ_ЛОГОВ
```

Вместо примеров укажите реальные числовые ID. Альтернатива — переменные
`TELEGRAM_PAYOUTS_CHAT_ID`, `TELEGRAM_EVENTS_CHAT_ID`, `TELEGRAM_GAMES_CHAT_ID`.
Привязка через команду сохраняется в данных сервера и имеет приоритет над `.env`.
`/chatid` показывает ID чата, если команду присылает администратор.

Очередь логов сохраняется на диске. До привязки канала события остаются в очереди.
При сбоях доставки отправка повторяется; Telegram ограничивает частоту публикаций,
поэтому при большой нагрузке журнал в приложении обновится раньше канала.
Доставка уведомлений — как минимум один раз: при обрыве связи после принятия
сообщения Telegram возможен повтор сообщения с тем же ID операции. Финансовое
начисление или решение по выводу при этом повторно не выполняется.

## Команды

Для игрока: `/start` (приветствие с крокодилом и кнопками), `/profile`, `/wallet`,
`/ref`, `/support`. В приветствии доступны «Играть», «Профиль», «Рефералы», «Поддержка».
Пополнение/вывод из профиля бота открывают соответствующую вкладку кошелька Mini App.

Только администратору, в личном чате:

- `/stats ID` — история ставок с результатами, коэффициентами и страницами.
- `/balance ID` — история операций с суммами и статусами.
- `/ref ID` — рефералы игрока, депозиты, заработок и страницы.
- `/kassa` — кнопки «Сегодня», «Неделя», «Всё время», «Обновить».

День в кассе считается по UTC; «Неделя» — последние семь календарных дней,
включая текущий. Пополнения учитываются только после подтверждённого зачисления,
выводы — только после отметки об успешной выплате. Заявки показаны отдельно.
Денежный поток = пополнения минус выплаченные выводы. Игровой результат = доход
проекта от игр против проекта минус реферальные начисления. Это **не чистая прибыль**:
расходы, бонусы, комиссии и налоги не вычитаются, поскольку их полного учёта в коде нет.
Покерные выигрыши между игроками не считаются доходом проекта.

## Выводы

По умолчанию `WITHDRAW_MODE=manual`: запрос резервирует сумму и создаёт заявку
«В обработке». В канал отправляются имя, @ник, ID, сумма, сервис и ID заявки.

- **✅ Выплачено** — подтверждает уже выполненный администратором перевод. Кнопка
  сама НЕ отправляет криптовалюту. Игрок видит «Успешно».
- **❌ Отказано** — меняет статус на «Отказано» и возвращает сумму на основной баланс.

Решение принимается один раз. Оно доступно только Telegram-администратору из
`TELEGRAM_ADMIN_IDS` и только в настроенном канале выплат. Старая/повторная кнопка
не переводит деньги повторно. Автоматические старые выплаты нельзя пометить такими
кнопками; для неоднозначных ответов провайдера сохранён отдельный старый retry-механизм.
`WITHDRAW_MODE=automatic` сохраняет прежнюю автоматическую схему, если она нужна
оператору; для согласованной ручной обработки оставьте `manual`.

## Реферальные расчёты

Новый аккаунт закрепляется при первом входе `/start ref_ID` или подписанном
`start_param=ref_ID`. Существующие аккаунты не перепривязываются. Самоприглашение
не даёт связи. Базовая ставка — 10%.

После каждого завершённого раунда к результату реферала добавляется ставка минус
выплата. Комиссия начисляется лишь с превышения ранее достигнутого положительного
результата. Минус переносится отдельно по каждому рефералу. Уже начисленная комиссия
не забирается. Суммы хранятся в центах; дробные центы накапливаются через расчёт
совокупного результата, а не округляются отдельно на каждой маленькой ставке.

«Забрать на баланс» переводит всю доступную сумму сразу и атомарно записывает
операцию. Повторный запрос при пустом реферальном балансе ничего не начисляет.
Депозиты служат статистикой и не являются основанием комиссии.

Важное ограничение существующего единого игрового баланса: обычные ставки,
административные начисления и бонусные деньги не разделены на разные кошельки.
Для реального платёжного запуска не выдавайте бесплатный выводимый стартовый баланс:
задайте `START_BALANCE=0`. Ставки из ранее выданных средств тоже участвуют в текущем
игровом результате. Невыплаченные оператором расходы эта модель не знает.

## Хранение и восстановление

Балансы, рефералы, ставки, платежи и очередь Telegram сохраняются совместно в
`DATA_DIR/accounts.json` через запись временного файла и переименование. При
ошибке сохранения новые денежные операции отменяются, а клиент получает восстановленное
состояние. Старый `payments.json` используется только для первоначального импорта;
после миграции источником истины является `accounts.json`.

Перед обновлением сохраняйте резервную копию всего `DATA_DIR`. Для восстановления
нужна согласованная копия кода и данных: старые версии кода не сохраняют новые поля
журнала и не умеют обрабатывать ручные заявки. Не откатывайте финансовые данные
поверх операций, которые уже произошли после резервной копии.

История не обрезается до последних 30 записей: интерфейс и бот используют страницы.
Хранилище JSON рассчитано на небольшой проект; при росте журнала следует перенести
эту же модель операций в транзакционную базу данных.

## Проверки

`node --test test/*.test.js`. Новые проверки покрывают привязку рефералов, немедленное
начисление и перенос минуса, повторные операции, отказ диска, восстановление платежей,
права бота, ограничения слотов и реальные WebSocket-запросы. Секреты и реальные
платёжные сервисы в тестах не используются.

Макеты переведены в HTML/CSS с реальными контролами. Программная проверка ресурсов
выполнена. Визуальная проверка в Telegram не выполнена в этой среде: браузер отсутствует,
загрузка браузера заблокирована сетью; точное пиксельное совпадение не подтверждено.

## Диагностика задержек

После обновления медленные операции автоматически пишутся в journal с `[perf]`:
`accounts.snapshot` — копирование состояния перед транзакцией (от 100 мс),
`accounts.save` — сериализация JSON и запись на диск (от 100 мс),
`accounts.atomic` — вся транзакция и уведомления (от 200 мс),
`ws.handle` — обработка входящего сообщения приложения (от 200 мс),
`event_loop` — опоздание секундного таймера (от 200 мс),
`telegram.МЕТОД` — запрос Telegram, включая чтение ответа (от 1000 мс),
`bot.handle` — обработка одного обновления бота (от 1000 мс),
`bot.batch_wait` — ожидание внутри уже полученного пакета обновлений (от 1000 мс).
Последнее не измеряет время сообщения до получения от Telegram.
Обычный `getUpdates` исключён: его долгое ожидание предусмотрено протоколом.
Время обработки на сервере не включает сеть до телефона и клиентские анимации.
Вложенные замеры пересекаются, их нельзя складывать.

```bash
sudo journalctl -u poker --since "15 minutes ago" --no-pager | grep -F '[perf]'
```

Повтор одного вида предупреждения ограничен одним сообщением за 5 секунд;
`suppressed` — число пропущенных повторов
с прошлого сообщения этого вида. Тексты сообщений, ID игроков, токены,
платёжные данные и содержимое запросов в эти строки не включаются.
`PERF_LOG=0` отключает диагностические записи после перезапуска.
